# Docling Strategy

## What Docling Does

Docling is the extraction engine responsible for processing manufacturer PDFs and product guides into structured raw content.

Docling extracts:
- Text blocks per page
- Tables (as structured JSON where possible)
- Layout structure (headings, sections, columns)
- Page-level metadata and boundaries
- Bounding box or positional data where available

Docling does **not**:
- Decide what is "correct" BuildQuote data
- Map extracted content to BuildQuote schema fields
- Generate system cards or component records
- Make trust decisions

Docling produces raw material. The AI parser interprets it. Human verification decides trust.

---

## Role Boundaries

```
Docling
  → extracts text, tables, layout
  → stores raw output in document_pages and document_chunks

Chunk classifier
  → categorises chunks by content type
  → does not interpret values

AI parser (Claude)
  → reads classified chunks
  → suggests structured staged records
  → marks all suggestions as AI-generated, not verified

Human reviewer
  → sees original PDF page beside AI-suggested record
  → approves, rejects, or edits each field
  → only approved data can be exported
```

---

## Page Number Preservation

Page numbers are the visual anchor between the AI-suggested data and the original source document.

Every `document_chunks` row must carry an accurate `page_number`. This is how the verification UI knows which PDF page to show beside a field being reviewed.

Rules:
- Page numbers from Docling output must be stored exactly — do not renumber or reindex.
- `document_pages.page_number` must match the actual page number in the PDF (1-indexed).
- `field_verifications.source_page_number` must reference the same page numbering.
- If Docling returns 0-indexed pages, the ingest step must convert to 1-indexed before writing to Supabase.

---

## Table Preservation

Product specification tables are often the highest-value content in a manufacturer product guide. They contain SKUs, dimensions, UOM values, and component listings.

Rules:
- Tables extracted by Docling should be stored as JSON in `document_chunks.table_json`.
- Do not flatten tables to plain text — the JSON structure preserves row/column relationships needed by the AI parser.
- `document_chunks.raw_text` may still contain a text rendering of the table as fallback.
- The AI parser prompt for components (`prompts/component_extraction.md`) should prefer `table_json` over `raw_text` when available.

---

## Page Preview Images

The verification UI shows the original PDF page beside the AI-suggested system card. This requires per-page images.

Strategy:
- Page preview images are not generated by Docling itself (Docling is a text/table extractor).
- Page images should be generated as a separate step — either during the Docling run or as a post-processing step using a PDF rendering library (e.g. `pdf2image`, `pypdfium2`).
- Each page image is stored in R2 at:
  ```
  manufacturers/{manufacturer_slug}/page-previews/{source_document_id}/page-{page_number}.png
  ```
- The R2 key for the page image is stored in `document_pages.page_image_storage_key`.
- The verification UI retrieves page images via server-generated signed URLs (short TTL).

---

## Docling Output Format

Docling can output structured JSON per page. This JSON should be stored in:
- `document_pages.docling_json` — page-level Docling output
- `document_chunks.docling_json` — chunk-level Docling output (bounding boxes, type metadata, etc.)

Storing the raw Docling JSON allows future re-processing without re-running Docling against the PDF.

---

## Extraction Confidence

Where Docling or the chunk classifier produces a confidence score, it should be stored in:
- `document_chunks.confidence` — classifier confidence for chunk type assignment
- `staged_systems.extraction_confidence` — AI parser confidence for the system record
- `staged_components.extraction_confidence` — AI parser confidence for the component record
- `field_verifications.confidence` — field-level confidence

Low confidence fields should be visually flagged in the verification UI to draw reviewer attention.

---

## Re-extraction

Docling extraction is idempotent at the document level if the pipeline writes cleanly:
- A new `extraction_runs` row is created for each run.
- `document_pages` and `document_chunks` may be re-created or appended depending on strategy.
- Staged records from a previous extraction run should not be silently overwritten — create new staged records linked to the new extraction run and let the reviewer manage which version to keep.

For the first vertical slice, re-extraction is out of scope. One run per document is sufficient.
